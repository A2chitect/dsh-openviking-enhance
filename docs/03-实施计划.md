## P2：装入 profile 并在真实 GUI 里验证（下一步，需要你执行安装命令）

安装会写到本仓库之外的 profile 目录，因此这一步由你运行：

```bash
dsh plugin --profile desktop add link:/Users/a2chitect/AIplayground/DeepseekHarness/dsh-openviking-enhance
```

然后重启 app / 重载 profile。验收清单：

1. **左侧出现 OpenViking 行**：点击后中央区域加载 Studio（网络面板可见
   `127.0.0.1:1933/studio/` 的 200）。
2. **Studio 功能正常**：能切换 Studio 内部页面、能看记忆列表（证明 same-origin
   与 `localStorage` 都没被破坏）。
3. **状态 pill 出现**：位置在输入框下方、上下文占用条同一行；当前会话（无提交）
   显示"未提交"，`pending_tokens` 随对话增长。
4. **点击 pill 展开**：能看到 `dsh-session-<id>`、提交次数；有 archive 的会话上
   点某一档能列出新增/更新/删除的记忆 URI。
5. **抽取中状态**：等一次真实提交（或对一个已提交会话观察新 archive），
   pill 显示"抽取中…"，随后变为"N 次提交"。
6. **坏路径降级**：停掉 OpenViking（`launchctl bootout gui/$(id -u)/ai.openviking.server`
   或改 `endpoint` 指向空端口）→ 面板显示错误卡片、pill 显示"不可用"，**GUI 不崩**。
7. **不污染既有功能**：正常对话、OpenViking 自动召回/提交仍工作。

排查要点：

- client bundle 未构建 → 启动日志会明确报缺失的 `lib/client.js`；
- slot 名不匹配 → 打开 DevTools 看是否有 `openviking-enhance` 的 warn；
  最权威的做法是打开带 token 的 GUI 地址后，用 `client/Slots.listSubTree` 查真实 slot 树；
- 路由打不通 → 确认请求是相对路径（Network 面板里的实际 URL）。

## P3：体验打磨

| 项 | 说明 |
| --- | --- |
| 提交历史视图 | 现在是"archive 列表 + 点开看 diff"；可加时间线（archive 的 `modTime` 已有） |

## P4：可选增强（需要先确认需求）

| 项 | 前置条件 |
| --- | --- |
| 手动"立即提交"按钮 | 会写数据（`POST /api/v1/sessions/{id}/commit`）——与当前"只读"定位冲突，需要单独确认 |
| 提交策略 UI（token 阈值 / turn 阈值） | 需要写 `ov.conf` 或走配置接口；`commitTurnThreshold` 目前在插件里是死配置，要真正生效必须改插件 |

## 风险与回滚

| 风险 | 处置 |
| --- | --- |
| 插件导致 GUI 启动失败 | 已按 shell 的失败语义做了 try/catch；兜底是 `dsh plugin --profile desktop remove dsh-openviking-enhance` |
| DSH 升级改 slot 名 | slot 名集中在 `src/client/index.tsx` 一处；`slots.inject` 保证缺失时只是不注册 |
| OpenViking 升级改 diff 结构 | 解析集中在 `normalizeDiff()`；测试用 `scripts/smoke-host.mjs` 可随时回归 |
| `runtime.states` 被上游改成私有 | 已有降级路径（`dsh-<id>` / 空 peer / null 阈值），最坏情况丢失"进度分母"和 peer 作用域会话的读取 |
| 仓库自带的 pnpm store 变大 | `.pnpm-store/` 与 `.npm-cache/` 已 gitignore；换机器可直接删掉 `.npmrc` 里那两行 |
