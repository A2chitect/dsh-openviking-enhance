# 技术方案

## 1. 总体形态

一个包，两个面（dual-face bundle），一条 patch 行同时挂载：

```
package.json
├── exports["."]        → lib/index.js     host 进程（Cordis 插件）
├── exports["./client"] → lib/client.js    browser（懒 CJS 工厂）
├── dsh.bundle.patch    → cordis.patch.yml 插入 id: openviking-enhance
└── dsh.client          → { platform: "web", inject: [4 个 UI 包] }
```

选这个形态的原因：DSH 的 `main`/`sidebar` 是 root 作用域的结构位，必须由 browser 半边注册；
而 OpenViking 的 HTTP 读取必须在 host 进程（有 fs、无跨域）。两者是同一个功能的两端，
拆成两个包只会多一份 patch 和一套版本对齐成本。已装的两个第三方插件
（`@linxin666/dsh-client-ui-task-board`、`@linxin666/dsh-client-ui-skill-explorer`）都是这个形态。

## 2. Host 半边

### 2.1 生命周期与降级

```ts
export const name = 'openviking-enhance'
export const inject = ['webServer']          // 唯一硬依赖
export const Config = z.object({ … })        // schemastery，全部有默认值
export function apply(ctx, config) { … }
```

- **`openvikingMemory` 不需要是被 inject 的依赖**：`ctx.get('openvikingMemory')` 在每次
  状态请求时惰性读取，插件没装也能跑（降级见 §2.4）。
- **不写任何数据**：本插件对 OpenViking 只读。不提交、不写入、不删除。
- **不抛异常**：四个路由的 handler 全部返回 `{ok:false,error}` 而不是 throw；
  `apply()` 本身只做注册，失败也只记日志。

### 2.2 配置解析（`src/host/config.ts`）

优先级：插件 config → `OPENVIKING_*` 环境变量 → `~/.openviking/ovcli.conf`
（`url`/`api_key`）与 `ovcli.conf.local`（`account`/`user`）→ 内置默认值
（`http://127.0.0.1:1933`、`default`/`default`）。

复用 OpenViking 自己的配置文件而不是另起一份，保证面板展示的记忆空间和 session
实际写入的空间是同一个。`apiKey` 永不进日志：诊断输出走 `describeConnection()`。

### 2.3 路由（`/api/openviking-enhance/*`）

| 路由 | 作用 | 关键实现 |
| --- | --- | --- |
| `GET /config` | 面板启动：endpoint、studioUrl、健康状态、版本、身份、警告 | `/health` 失败也返回 200，只把 `healthy:false` 与警告文案给前端 |
| `GET /status?sessionId=` | 提交状态 | `sessions/{id}` + `fs/ls history` 并行；2.5s 缓存；archive 数领先计数器时再探测该 archive 的 `memory_diff.json` 判定"抽取中"还是"计数器滞后" |
| `GET /commits?sessionId=` | 状态 + 本次 session 的 commit 任务 | tasks 只用于标注"抽取中" |
| `GET /diff?sessionId=&archive=` | 某次提交影响的记忆 | 读 `memory_diff.json`；404 时返回 `{ok:true, diff:null, pending:true}` |

`/diff` 的 `archive` 参数有白名单校验（`isArchiveUriForSession`）：必须是
`viking://` 且落在**该 session 自己的** `history/archive_` 下，不含 `..`。
否则这个路由会变成任意 `viking://` 文件读取器。

**所有路由都过 trust fence**（`src/host/trust-fence.ts`）：socket 地址必须是 loopback、
`Host` 必须是 loopback 权威、`sec-fetch-site` 不得为 `cross-site`、`Origin`（若存在）
必须与 `Host` 同源，非 GET 一律 405。原因：**DSH 的 Web 鉴权门只覆盖文档路由**——
实测 `GET /` 无 token 返回 401，而 `GET /api/openviking-enhance/config` 裸 curl 返回 200。
本机 loopback 下没有增量风险（同机进程本来就能直读 `~/.openviking`），但一旦 DSH 监听
非 loopback 或经隧道/反代访问，这些路由（尤其返回记忆正文的 `/diff`）就变成一个
免鉴权的记忆读取接口。`X-Forwarded-For` 一律不采信。

### 2.3.1 会话路径来自服务端，不靠拼字符串

`history/archive_00N` 的路径**必须取会话自身的 `uri`**，而不是用插件配置的身份拼：

```
GET /api/v1/sessions/{id} → { "uri": "viking://user/<owner>/sessions/<sid>", "created_by_user_id": … }
```

优先级：`uri` → `created_by_user_id` → 配置的 user（最后兜底）。原因：会话可能属于
别的 user/peer 命名空间（本机就有 `fitbot`、`peers/hermes`），用配置身份拼路径会
**列不到 archive**，于是 phase 被误判为"未提交"——而它其实提交过。这是"看起来正常
但结论是错的"那类 bug。

代价是把原先并行的两个请求改成串行（多约 7ms），换来这一类误判彻底消失。
注意职责边界：`resolveSessionUri` 返回**会话目录**，`/history` 后缀由
`OpenVikingApi.listHistory` 负责——两边都拼会得到 `history/history`，
实测表现为所有会话 `archives: []`（已有单测锁死，见 `test/host-units.test.mjs`）。

### 2.4 降级矩阵

| 依赖 | 正常 | 降级 |
| --- | --- | --- |
| `openvikingMemory` 已挂载 | 从 `states.get(sessionId)` 取 `ovSessionId` / `peerId` / `commitTokenThreshold` | sessionId 用 `dsh-<id>`；peer 空；threshold `null`（UI 只显示原始 token 数） |
| OpenViking 在线 | 完整状态 | `phase: 'failed'`，pill 显示"不可用"，面板显示错误卡片 |
| archive 无 diff | 显示明细 | 显示"抽取仍在进行" |

`runtime.states` 是**未文档化**的公开 Map 字段。因此它只出现在"更好"的分支里，
全部读取都包在空值判断中；HTTP 路径完全不依赖它。

### 2.5 为什么状态是轮询而不是事件

commit 发生在 OpenViking 进程里，DSH 侧没有任何可订阅的信号（§可行性分析 2.2）。
可选方案里：

- 猴补丁 `runtime.client.commitSession` —— 能拿到 `task_id`，但会漏掉队列重放的提交
  （`pending-queue.mjs` 直接 `fetchJSON`，不经过该方法），且会随插件升级失效；
- 监听日志 —— debug 级别被 exporter 过滤，根本没有日志；
- **轮询服务端 —— 选它**。实测成本 session 详情 ~1KB/7ms、`fs/ls` ~0.5KB/8ms，
  服务端再加 2.5s 缓存，5s 一次完全可接受。

## 3. Client 半边

### 3.1 三个注册点（`src/client/index.tsx`）

```ts
slots.inject('sidebar.panellist', () => slots.register(
  { name: 'sidebar.panellist', id: 'openviking', order: 30, label: () => 'OpenViking' },
  StudioIcon))

slots.inject('main', () => slots.register({ name: 'main', key: 'openviking' }, StudioPanel))

slots.inject('conversation.composer.dock', () => slots.register(
  { name: 'conversation.composer.dock', id: 'openviking-commit', order: 0,
    inject: (sessionId) => ({ sessionId }) },
  CommitStatusPill))
```

- 用 `ctx.slots.inject(key, cb)` 而不是直接 `register`：`inject` 会**等待 slot 声明**，
  当 DSH 版本里没有这个 slot 时安静地不注册，而不是撞上 SlotCore 的"未声明 slot"抛错。
- `sidebar.panellist` 与 `main` 必须**成对**注册：点击一个 `main` 里不存在的 key 会让
  shell 抛错。冒烟脚本里有一条断言专门锁这个不变量。
- 组件只画图标那一格；行按钮、标题、tooltip、选中高亮都由 shell 提供。

### 3.2 为什么状态条挂在 `conversation.composer.dock`

| 候选 slot | 作用域 | 评价 |
| --- | --- | --- |
| `conversation.composer.dock` | session | **选它**。输入框下方的 flex 行，与上下文占用条（ContextMeter）同一行；session 作用域，`inject` 直接拿到 `sessionId` |
| `conversation.session.header.utilities` | session | 会话标题右侧胶囊位，也可用；但状态类信息更贴近 composer |
| `sidebar.footer.action` | root | 左下角，拿不到 sessionId，不满足"每个 session"的诉求 |

`composer.dock` 是共用的一行，因此只放一个 pill（不是整块面板）；明细走点击弹出的 popover。

### 3.2.1 位置与样式：与默认 pills 同族，排在它们后面

**位置**：pill 就是底栏里的一个普通 flex item，`order: 1` 让它在默认统计 pills
与上下文占用条之后渲染，整行的居中由 shell 自己负责——我们不加任何占位、不吸空白。

这里有两个实测踩出来的前提，值得记下来，免得以后又"想当然"：

| 事实 | 出处 | 后果 |
| --- | --- | --- |
| slot 出口外层是 `<div data-slot style="display:contents">` | `dsh-client-ui-renderer` 的 `ANCHOR_STYLE` | 条目本身就是底栏的 flex item；也因此**绝对定位会跑到无关祖先上**，不能用 |
| `.yhfFVG_dock` 的父级是 `flex-direction:column; align-items:center` | `InputBar.module.css` | dock 宽度**收缩到内容**（fit-content），内部没有可分配空白 |

第二条是本次返工的根因：dock 无空白 ⇒ `margin-left:auto` 完全不生效；
为"平衡"而加的等宽镜像只会多占宽度，把整组推右（截图实测整组右偏约 69px，
与镜像半宽吻合）。撑宽 dock（`:has()` + `width:100%`）能生效，但既然需求只是
"跟在默认 pills 后面"，就用最简单的形态，**不引入任何对 shell 布局的改写**。

**样式**：逐条复制 `StatsPills.module.css` 的声明，不另立一套：

| 项 | 取值（与默认同源） |
| --- | --- |
| 字号 | `calc(var(--dsh-content-font-size-secondary, 13px) - 1px)` |
| 行高 | `calc(20px + var(--dsh-content-font-delta-secondary, 0px))` |
| 文字色 | `var(--dsw-alias-label-tertiary)` |
| 悬停/展开 | `var(--dsw-alias-interactive-bg-hover)` + `label-secondary` |
| 形状 | 透明、无边框、`border-radius:999px`、`padding:1px 8px`、`gap:6px` |
| 图标 | 14×14、`currentColor`、1px 描边 |
| 数字 | `font-variant-numeric: tabular-nums` |

**图标与身份标识**：pill 用与左侧边栏面板行**同一个**图形
（`src/client/openviking-icon.tsx` 单一来源，两个挂载点共用一份 SVG 定义），
所以侧边栏那一行和状态栏说的是同一件事。图形本身是"两个相连节点 + 开放环"的
知识图谱标记，刻意不用通用的 archive/database 图标——否则容易和 git commit、
token 计数混淆。文字上再以 `OV ·` 前缀做第二重区分（14px 图形不足以承担辨识时，
文字兜底）。描边粗细做成参数：侧边栏 16–18px 用 1.3，状态栏 14px 与默认 pills
一致用 1（同尺寸下 1.3 会明显偏粗）。

弹窗沿用 `stat-dialog.module.css` 的令牌，标题写全名 `OpenViking 提交`。

### 3.3 相对 URL（易错点）

前端请求必须写成**文档相对路径** `api/openviking-enhance/status`，不能是
`/api/openviking-enhance/status`。shell 的 `<base href="./">` 支持子路径部署
（`/dsh/dsh/`），根绝对路径会绕过该前缀、永远打不到插件的路由。

### 3.4 构建（`build.mjs`）

| 面 | 产物 | 关键设置 |
| --- | --- | --- |
| host | `lib/index.js` | ESM / node22，`external: ['@deepseek-ai/*']` |
| client | `lib/client.js` | CJS / browser，`external: [react, react/jsx-runtime, react-dom/client, @deepseek-ai/cordis, @deepseek-ai/dsh-client-ui-primitives]`，外加懒 CJS banner/footer |

客户端产物结构（与已发布插件逐字同构）：

```js
window.__ModuleLoader__.load({
  id: "dsh-openviking-enhance",
  factory: (require) => {
    var module = { exports: {} }; var exports = module.exports;
    /* esbuild CJS bundle，require("react") 由 shell 的冻结模块表提供 */
    return module.exports;
  }
});
```

**React 绝对不能打包进来**——shell 的模块表是单例，打包会导致 hooks 拿到第二份 React
而报错。冒烟脚本里有一条断言检查产物不含 react 运行时。

### 3.5 失败策略

shell 在插件 `apply()` 抛错时会让**整个 web 界面启动失败**。因此：

- `apply()` 全体包在 try/catch 中，只 `logger.warn`；
- 所有 disposer 经 `ctx.effect` 托管，卸载/HMR 时一次性回收；
- React 组件内部对 host 路由失败做 `{ok:false}` 渲染，不 throw。

## 4. 被否决的方案

| 方案 | 否决原因 |
| --- | --- |
| 在 OpenViking 里加"按会话列 commit"接口 | 需要改 OpenViking 源码；archive 目录已经提供了等价信息 |
| 用内置 Browser 页签打开 Studio | 地址解析器拒绝 DSH 自身 origin，也拒绝把 studio 代理到 DSH 端口；且固定在 `127.0.0.1:1933` 反而让它保留 same-origin 语义 |
| 把 Studio 代理到 DSH origin | Studio 依赖相对 `/api/v1` 与 `localStorage`，换 origin 会直接坏掉；且无 CORS/frame 阻碍，代理没有收益 |
| Typert Remote RPC | browser 侧需要 strict codec（codegen 或手写 descriptor），而 HTTP 路由是已装插件验证过的路径，无 codegen |
| 猴补丁第三方插件对象 | 会随升级失效，且漏掉队列重放的提交 |
| 复制一份 memory_diff 逻辑（自己算增量） | 服务端已产出权威 diff，自算只会引入误差 |

## 5. 与第三方插件的关系

| 交互 | 方式 | 耦合度 |
| --- | --- | --- |
| 读 OpenViking 数据 | 自己的 HTTP 客户端 | 无 |
| 取 `ovSessionId` | 可选读 `openvikingMemory.states` | 弱（有降级） |
| 取 `peerId` | 同上 | 弱（有降级） |
| 取 `commitTokenThreshold` | 同上 | 弱（`null` 即隐藏分母） |
| 改第三方代码 | 无 | —— |

升级 `@openviking/dsh-memory-plugin` 不需要改本插件；只有 OpenViking 服务端改
`memory_diff.json` 结构时才需要动 `normalizeDiff()` 一处。
